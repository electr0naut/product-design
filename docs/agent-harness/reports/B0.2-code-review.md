Two correctness bugs must be fixed before `gatekeeper` relies on it. Both make the gate pass, or flag the wrong
tests, when something upstream goes wrong.

## Must fix

**1. A failed test collection is treated as "no tests" (`collect_ids`, lines 97-103).** When the collect command
exits non-zero and prints no test ids, the function returns `[]` without saying anything. If collection fails on
the **base** commit (a broken import, a syntax error, a missing dependency):
- `base_ids` is empty, so **every existing test counts as new**;
- existing tests then pass on base and get flagged `passes_on_base`;
- the `test-critic` stage is told to **delete existing tests**.

A partial collection (pytest exit 2 with some ids printed) is also accepted as complete.

- **Fix:** if the exit code is not 0, raise `HarnessError` naming the commit, the command and the last lines
  of output. The exception is pytest's 5 ("no tests collected"), which is a legitimate empty result.
  `main` already turns that into exit 2.
- **Tests:**
  - a base commit with a syntax error in an existing test makes the gates exit 2, and flags nothing;
  - a head commit with a collection error also makes them exit 2.

**2. AC coverage trusts the implementer's own list (`run_gates`, lines 153-160).** `missing_acs` only checks the
criteria the implementer listed in `implement.json`. If the implementer leaves a criterion out, or returns an
empty `ac_tests`, nothing is reported missing and the gate **passes with no tests for that criterion**.

- **Fix:** add `--acs <readiness.json>`, the triage output, which is the source of truth. Every
  `acceptance_criteria[].id` that has no valid test is missing, whether or not the implementer mentioned it.
  Keep `implement.json` only for the mapping from criterion to test ids. If `--acs` is missing, exit 2; don't
  fall back silently.
- **Tests:**
  - with readiness listing AC1 and AC2 and an implement map naming only AC1, AC2 is missing and the gate fails;
  - with an empty `ac_tests`, every criterion is missing.
