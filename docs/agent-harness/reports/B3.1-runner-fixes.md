1. **Path traversal in `prove`.** `test_file` and `test_id` from the model are untrusted now: `safe_rel_path` refuses absolute paths, `..`, a leading `-`,
   anything that does not match `commands.test_globs`, and anything whose resolved path leaves the scratch or clean worktree. `test_id` must start with `test_file`
   and cannot begin with `-`. A refused path gives `proven: null` with a note. Tests: `/etc/hostname`, `../../x.py`, `tests/../../x.py`, `-p/x`, and a non-test path;
   nothing is written outside the worktrees.
2. **Only a real assertion failure is proof.** The re-run writes a JUnit report (`--junitxml`); `proof_outcome` counts it as proven only if the first `E` line of the
   failure is an `assert`/`AssertionError`, or an exception class named in the finding's own `failure` text. A setup/collection error, a NameError in the test, or any
   other exception gives `proven: null` with the exception type. A passing test gives `false` (disproved). Tests: assertion -> true; NameError -> null (the finding
   then shows as blocking-unproven, not proven); a named `ZeroDivisionError` -> true.
3. **No paid retry loops.** `subprocess.TimeoutExpired` is caught and the card is blocked as `transient`. Each card gets one attempt: an attempt counter in
   `work/reviewer-attempts.json` is written before the claim; a card that comes back `ready` after an unfinished attempt (timeout, crash, killed runner) is blocked
   as `needs_input` without a review. A successful review clears the counter. Tests: timeout blocks transient; a second pass gives up with two kanban calls only.
