## Must fix before the rerun: the host runs git *inside* the container-writable repo

While checking the trusted-repo change I found a container-to-host path that has existed since B3. The host
reviewer runner (as `ubay`) runs git directly in `work/fixture-repo` and `work/variant-repo`. That's
`self.repo` in `reviewer.py`: `worktree add` at lines 339, 375 and 388, `diff` at lines 60 and 409, `show`,
`cat-file` and `symbolic-ref`. Workers can write that repo's `.git/`. Git runs code from a repository's own
`.git` in several cases:

- **`.git/hooks/post-checkout`** runs on `git worktree add`. That is arbitrary code on the host as `ubay`, at
  every refute and every prove.
- **`core.fsmonitor`** in `.git/config` runs a command on index-reading operations.
- **Diff drivers and textconv** (`diff.<name>.command`, `.textconv`), defined in `.git/config` and selected
  by `.gitattributes`, run on `git diff` and `git show`.
- **`filter.<name>.smudge`** runs on checkout.

So the B5 rule, that the host never executes repository code, is broken through git itself.

**Fix: the host never runs git in a work repo except to fetch from it into the trusted repo.**

1. **Fetch:** use `git -C <trusted> -c core.hooksPath=/dev/null fetch --no-tags <work-repo>
   +refs/heads/harness/<KEY>:refs/incoming/<KEY>` (and `variant/*` likewise). A local fetch runs
   upload-pack in the work repo, but its dangerous hooks are honoured only from protected (system or global)
   config, not from the repository's own `.git/config`.
2. **All other host-side git runs in the trusted bare repo**, whose config and hooks only the host can write.
   That covers `diff`, `show`, `cat-file`, `merge-base`, the changed-line parsing, and `worktree add` for the
   refute and prove worktrees (still created under `work/prove/` so the container can run the proof). Pass
   `-c core.hooksPath=/dev/null -c core.fsmonitor=false`, and use `--no-ext-diff --no-textconv` on diffs.
3. **Path changes:** `read_run_files` validates `base` against the trusted repo; `changed_lines`, `excerpt`
   and the review diff read `refs/incoming/<KEY>`; the work repo's `symbolic-ref` check is dropped, since
   `sync_work_main` is the only remaining host write to the work repo. That write is `update-ref`, which
   runs no hooks.
4. **`sync_work_main`:** make it `git -c core.hooksPath=/dev/null update-ref`. If you can, write
   `refs/heads/main` through the trusted repo as a push (`git -C <trusted> push <work-repo>
   +<sha>:refs/heads/main`). A push into a container-writable repo would run *its* receive hooks on the
   host, though, so **don't** do that. Keep the hardened `update-ref`.
5. **Tests:**
   - a work repo with an executable `post-checkout` hook that writes a marker file outside the repo. After a
     full review (refute, prove, approve), the marker must not exist;
   - the same for a `core.fsmonitor` command and a `diff.x.textconv` driver with `.gitattributes`.

The gates run inside the container, so their git use on the work repo is fine. They're already on the
container side of the boundary.
