## D5.1, the rename bypass: what changed
The review is right that root-owning a folder does not stop a worker that **owns its parent** from renaming it away and putting its own in its place; `hermes` is uid 1000 and owns `/srv/lab/agent-harness` and `work/`. Today that makes tonight's `chown` of `.venv-container` and `work/js-deps` bypassable.
1. **The JS dependencies leave `work/`.** The overlay's `commands.deps_dir` is now `/srv/lab/agent-harness/deps/js/node_modules` (`eval/fixture-js/harness.js.toml`); the Stryker skip condition in `tests/test_mutation.py` follows; `deps/` is gitignored. New config test: no `deps_dir` in any config or overlay is under `/work/` and each is under `/srv/lab/agent-harness/deps/`.
2. **The physical move** (mine, with your go, before the sudo; `work/` and `deps/` are both `ubay`-owned, so a rename needs no sudo): `mkdir -p /srv/lab/agent-harness/deps && mv /srv/lab/agent-harness/work/js-deps /srv/lab/agent-harness/deps/js`. It must go together with merging this branch, because the live JS config otherwise points at the old path; no JS ticket is running now. Undo: move it back and revert the config.
3. **Reinstalling JS dependencies later** needs `sudo` once `deps/` is root-owned (`npm install` as `hermes` cannot write there): e.g. `sudo chown -R ubay:ubay deps && ...install... && sudo chown -R root:root deps`.
