## D3.1 (`7ce721e`): a fix pass may not touch existing tests (from the D2.1 review addendum)
- **Fix pass:** after a gates PASS on a ticket that has used its pass, the host gatekeeper compares the retry's head with the **first attempt's head** (the ledger's `head`) and blocks the card `needs_input` if any test file that **exists on base** differs (edited or deleted), naming the files; it never reaches the review. A test the ticket added in its first attempt is not on base, so it can still be fixed (even deleted). An unreadable ledger blocks too. Gate failures still go through the one-pass logic first.
- **First pass:** a diff that edits (`M`) or deletes (`D`) a test existing on base is now a **high-risk** signal in `risk.classify` (reason names the file), so it gets the full review.
- Tests: fix pass that deletes or edits a base test is detected (real git); a fix pass that edits or deletes a first-attempt test is not; the gatekeeper blocks (and does not complete) when the helper reports base tests, compares against the first head, and does nothing on a first pass; an unreadable ledger blocks; `touched_base_tests` reads M and D, not added files; a review goes high when a base test is touched.
