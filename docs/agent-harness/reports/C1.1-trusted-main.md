## Trusted main
- New module `harness.trusted`. The bare repo lives at `~/.local/state/agent-harness/trusted/<repo-name>.git`. The container mounts only `/srv/hermes/data` and `/srv/lab`, so it cannot see it. Only the loader and the reviewer runner write it.
- **Load:** creates the trusted repo from the work repo's `main` if missing. Otherwise it resets the work repo's `main` to the trusted one (also when a worker moved it ahead). A work `main` unrelated to the trusted one is an error ("delete <path> for a fresh run"), never a silent re-trust.
- **Approval (`advance_main`):** requires trusted main == `base.txt`; fetches `harness/<KEY>` into the trusted repo; requires trusted main to be its ancestor; `update-ref main <branch> <old>`; then mirrors the new sha into the work repo's `main` and into `work/trusted-main.txt`. A missing trusted repo fails closed.
- **Gates (`gates.require_trusted_main = true` in both tomls):** `base` must equal the copy in `work/trusted-main.txt`; a missing copy, a missing `work_dir` or a mismatch is an error, never a skip. The container can write that copy, so it is an early check only; the authoritative check is the host's `advance_main`.
- **Tests:** a worker commit on the work repo's `main` changes nothing in the trusted repo, the ticket still completes and both mains end on the ticket's branch; a stale base blocks and leaves trusted main alone; a missing trusted repo blocks; two tickets advance in order; gates fail (not skip) with the copy deleted, wrong or `work_dir` missing; load creates the trusted repo and resets a moved work `main`.
- **Scoring:** the hidden tests must run against the trusted `main` (for example `git -C <trusted> worktree add`). The scoring step is not automated yet.
