## The fixes the D1 review asked for (`70fb47e`)
1. **A proven bug stays proven until fixed.** A review-triggered pass stores each proof test (file, id, source) in **host-only** state, `~/.local/state/agent-harness/proofs/<KEY>/<n>/`, written by the runner right after the ledger entry; the ledger entry says how many to expect (`proofs_expected`). In the retry's review, **before the finder runs**, each stored proof is written into a clean worktree of the new head, run through `prove_cmd`, and judged by `proof_outcome`: still failing (True) or cannot run (None) blocks `needs_input` with no further pass; only when every stored proof passes does the fresh review continue. Missing or short stored proofs also block.
2. **Ledger fails closed.** Only a missing file is an empty ledger; unreadable or corrupt (or not a list) raises `HarnessError`, `request_fix` then refuses a pass (logs it), the card blocks as today, and the file is never rewritten.
3. **Swallowed `block` failure** is logged to stderr with the card id.
4. **Mixed proven + unproven findings: no retry** (`blocking and not blocking_unproven`).

Tests added (6 new in `tests/test_fixloop.py`, total 17): a stored proof that still fails blocks even though the finder reports nothing; a proof that now passes lets the review complete; a proof that errors blocks; proofs come from host state (editing every `fix-*.json` in `work/runs` changes nothing); missing stored proofs block; mixed findings block with no ledger entry; corrupt ledger blocks and is left byte-identical (and an unreadable one raises).
