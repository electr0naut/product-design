# J-20261127-3: the first kit job. Plain words in the alert script, on a branch, proved by the proof runner

**How to run commands in a job.** One command per Bash call. No `&&`, `;`, pipes, redirections or `echo`.
The commands a job may run are `git`, `uv`, `python3`, `ruff`, `ls`, `cat`, `sed`, `grep`, `find`, `head`,
`tail`, `wc`, `sleep`, and `touch` for a proof request only. If a single allowed command is refused, say so in
the report and stop.

## The change

or sends holds an emoji. `tools/harness_notify.py` still has four, at the start of four messages.

1. In the kit clone: `git checkout -b j3-notify-plain-words origin/master`
2. In `tools/harness_notify.py`, replace each emoji with a plain word that says the same, followed by a colon:
   the waiting message starts `waiting: `, the runner failure `runner failed: `... choose the words so that each
   message reads as a sentence and none repeats a word it already has. Change nothing else in the file.
3. In `tests/test_d11.py` (it already loads this tool): correct any expectation your change breaks, and add one
   test, named `test_notify_messages_are_plain_ascii`, that fails if any string literal in
   `tools/harness_notify.py` holds a character outside ASCII.
4. `uv run --with ruff ruff check tools/harness_notify.py tests/test_d11.py` and the same with
   `ruff format --check`. Fix what they report in the lines you touched.
5. Commit with a one-line message that says what changed. No model name and no session link in it.
6. `git push -u origin j3-notify-plain-words`. Never push `master`.

## The proof
7. Do not run the kit's tests yourself. Ask the proof runner: `git rev-parse HEAD`, then create the request
   with `touch /var/lib/harness-jobs/proof/requests/<that 40-character sha>`.
8. Wait for `/var/lib/harness-jobs/proof/results/<sha>.txt`: `sleep 60`, then `ls` the results folder; repeat,
   for at most 25 minutes. If no result has come by then, say so and stop.
9. If the result shows failed tests that your change caused, fix them, commit, push, and ask for one more
   proof of the new commit. One retry only.
