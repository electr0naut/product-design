# CLAUDE.md

## Project

Clone-per-product template for generating product lifecycle documents in order:
idea canvas, team analysis, BRD, PRD, technical design, user story backlog, and
implementation plan.

## Stack

- Markdown templates and prompts
- Python standard-library scripts in `shared/scripts/`
- Optional Claude CLI for document generation
- Lightweight Next.js dashboard in `src/app/`

## Agent and Engineering Rules

Read `AGENTS.md` before editing. It is the portable operational policy for any
coding agent. `ENGINEERING.md` is the canonical policy; behaviour-changing work
needs a concise spec under `docs/specs/`, regression tests for core pipeline
logic, and `make check` before completion.

## Commands

- Generate analyses: `python shared/scripts/generate_analysis.py --idea 01-ideation/<product>.md`
- Generate BRD: `python shared/scripts/generate_brd.py --idea 01-ideation/<product>.md --analysis 02-analysis/`
- Generate PRD: `python shared/scripts/generate_prd.py --brd 03-brd/<product>-brd.md`
- Generate technical design: `python shared/scripts/generate_technical_design.py --prd 04-prd/<product>-prd.md`
- Generate user stories: `python shared/scripts/generate_stories.py --prd 04-prd/<product>-prd.md --technical-design 05-technical-design/architecture/<product>-technical-design.md` (add `--epic E01` for one epic)
- Check backlog traceability: `python shared/scripts/validate_backlog.py --brd 03-brd/<product>-brd.md --prd 04-prd/<product>-prd.md`
- Generate implementation plan: `python shared/scripts/scaffold_code.py --technical-design 05-technical-design/architecture/<product>-technical-design.md`
- Prompt only: add `--prompt-only` to any generation command
- Regenerate an existing document: add `--force` (scripts never overwrite by default)
- Script tests: `python -m unittest discover shared/scripts/tests`
- Dev app: `npm run dev`
- Lint app: `npm run lint`
- Build app: `npm run build`

## Workflow Rules

- Treat earlier reviewed documents as the source of truth for later phases. The
  CLI supports iterative draft-to-draft exploration; approval remains a human
  workflow gate rather than an enforced status check.
- Keep generated documents traceable to their inputs.
- Edit phase documents in order: `01` before `02`, `02` before `03`, and so on.
- Do not overwrite approved product documents without confirming intent.
- Keep reusable instructions in `shared/prompts/`, not in generated output files.
- Keep templates generic enough to clone for unrelated products.
- Keep IDs stable: BR-xxx/NFR-xxx in the BRD, E01/US-001 in the PRD story map.
  Story files reuse them, and `validate_backlog.py` parses them.
- Run `validate_backlog.py` after editing stories; fix its errors before implementation.

## Directory Contract

- `01-ideation/` stores one or more product idea canvases.
- `02-analysis/<role>/` stores generated and reviewed analysis docs.
- `03-brd/` stores BRDs; `03-brd/approved/` may hold signed-off versions.
- `04-prd/` stores PRDs; `04-prd/approved/` may hold signed-off versions.
- `05-technical-design/` stores architecture, API, data model, and integration specs.
- `06-backlog/<product>/<E01-epic>/` stores one `US-xxx-<title>.md` file per story;
  `06-backlog/<product>/traceability.md` is generated by `validate_backlog.py`.
- `07-implementation/` stores generated implementation plans.
